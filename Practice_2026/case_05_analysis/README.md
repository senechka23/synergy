# Кейс-задача №5. Аналитический обзор

Для аналитического обзора выбрана кейс-задача №3 — веб-приложение на Django.

## 1. Краткое описание выполненной работы

В рамках кейс-задачи было создано простое веб-приложение на фреймворке Django. Пользователь может ввести своё имя в форму на главной странице. После отправки формы введённое имя проверяется, сохраняется в базе данных SQLite, а пользователю показывается персонализированное приветствие.

Для проекта была создана модель `Visitor`, содержащая одно поле `display_name`. Для работы с формой используется `ModelForm`. Обработка запросов выполняется во view-функции `welcome_page`. Интерфейс оформлен с помощью HTML и CSS. Для POST-запроса используется встроенная CSRF-защита Django.

## 2. Функциональность

Основная функциональность приложения реализована полностью: пользователь может открыть главную страницу, ввести имя, отправить форму, сохранить имя в базе данных и получить персонализированное приветствие. Пустое имя не сохраняется, а при некорректном вводе пользователь получает сообщение об ошибке.

Для учебного приложения данного набора функций достаточно, так как он покрывает условия поставленной задачи.

## 3. Производительность

Приложение выполняет небольшой объём операций: отображает одну страницу, проверяет одну строку и при успешной отправке добавляет одну запись в базу данных. Поэтому при локальном использовании задержки практически отсутствуют.

В качестве базы данных используется SQLite. Она удобна для небольшого учебного проекта, так как не требует отдельного сервера базы данных. Если приложение будет использоваться большим количеством пользователей одновременно, SQLite может стать ограничением. В таком случае можно перейти, например, на PostgreSQL.

## 4. Удобство использования

Интерфейс состоит из одного экрана, поэтому пользователь сразу понимает, что от него требуется. На странице есть заголовок, краткая инструкция, поле для ввода имени и кнопка отправки формы.

После отправки корректного имени приветствие показывается на той же странице. При попытке отправить пустое значение выводится понятное сообщение об ошибке.

Для улучшения интерфейса можно дополнительно добавить индикатор успешного сохранения данных и историю ранее введённых имён, но в рамках текущей задачи это не является обязательным.

## 5. Безопасность

В приложении применяется встроенная защита Django от CSRF-атак. В HTML-форме используется тег `{% csrf_token %}`, а в настройках проекта подключено стандартное middleware `CsrfViewMiddleware`.

Данные, которые выводятся через Django-шаблон, по умолчанию экранируются, что также снижает риск вставки нежелательного HTML-кода через поле имени.

Проект работает в учебном режиме с `DEBUG = True`. Для публикации приложения в интернете необходимо отключить режим отладки, вынести `SECRET_KEY` из исходного кода в переменные окружения и правильно настроить `ALLOWED_HOSTS`.

## 6. Масштабируемость

Структура Django-проекта позволяет добавлять новые возможности без полной переработки приложения. В дальнейшем можно добавить фамилию пользователя, дату регистрации, отдельную страницу со списком пользователей, удаление и редактирование записей, авторизацию или REST API. При росте проекта можно также заменить SQLite на серверную базу данных.

## 7. Сопровождаемость

Код разделён по назначению: модель находится в `models.py`, форма — в `forms.py`, обработка запросов — в `views.py`, маршруты — в `urls.py`, HTML-шаблон хранится отдельно, CSS вынесен в статический файл. Такое разделение делает проект понятнее и облегчает его изменение.

## 8. Переносимость

Проект может быть запущен на Windows, Linux и macOS при наличии Python. Необходимая внешняя зависимость указана в `requirements.txt`. SQLite хранит данные в одном локальном файле, поэтому для учебного запуска не требуется устанавливать отдельную СУБД.

## 9. Качество кода

В проекте соблюдено базовое разделение ответственности между компонентами Django. Код не содержит лишней логики, а обработка формы выполнена стандартными средствами фреймворка. Для проверки имени используется метод `clean_display_name`, что позволяет хранить валидацию рядом с формой. Проект специально не усложнялся дополнительными архитектурными слоями, так как является учебной работой небольшого объёма.

## 10. Тестирование

В приложении добавлены автоматические тесты средствами `django.test.TestCase`. Проверяются три базовых сценария: главная страница успешно открывается; корректное имя сохраняется в базе данных и отображается в приветствии; пустое имя не сохраняется.

Также приложение можно проверить вручную, отправляя разные значения через форму.

## 11. Проблемы, выявленные в ходе выполнения

### Проблема 1. Пустое значение имени

Если принимать данные напрямую из POST-запроса без проверки, в базе могут появляться пустые записи.

**Решение:** использовать Django-форму и дополнительную очистку значения методом `strip()`. Пустая строка после удаления пробелов считается ошибкой.

### Проблема 2. Защита POST-формы

Форма изменяет данные в базе, поэтому необходимо защитить POST-запрос от межсайтовой подделки.

**Решение:** использовать стандартный CSRF-механизм Django и тег `{% csrf_token %}` внутри формы.

### Проблема 3. Деление логики и интерфейса

Если разместить HTML, обработку данных и работу с базой в одном месте, код быстро станет сложным для поддержки.

**Решение:** использовать стандартную структуру Django: модель, форму, view-функцию, шаблон и CSS-файл.

### Проблема 4. Настройки для реальной публикации

Учебные настройки Django подходят для локального запуска, но не должны использоваться без изменений на публичном сервере.

**Решение:** при публикации отключить `DEBUG`, хранить секретный ключ в переменных окружения, настроить разрешённые хосты и использовать серверную базу данных при необходимости.

## 12. Итог

В результате выполнения кейса было создано небольшое работоспособное веб-приложение на Django, которое соответствует поставленным требованиям. Работа позволила применить на практике маршрутизацию Django, модели, формы, шаблоны, сохранение данных в SQLite, валидацию пользовательского ввода и CSRF-защиту.

Выявленные ограничения в основном связаны с тем, что приложение имеет учебный характер. При дальнейшем развитии его можно расширить, не меняя базовый принцип построения проекта.
